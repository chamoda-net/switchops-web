SwitchOps AI User Guide

SwitchOps AI is an on-premise network management platform for Cisco routers and switches and Huawei switches. It discovers your devices, keeps an accurate inventory, monitors health and traffic, raises incidents with AI root-cause analysis, and pushes configuration safely with checkpoints you can roll back to. Everything runs on your own server.

01Before you install

1.1What you receive from SwitchOps

ItemWhat it is
Installer (.run file)A single self-contained file. It needs no internet access, so it works on isolated and air-gapped networks.
Licence file (.lic)Your licence, tied to your server. You get it after you send us your server's fingerprint (see 2.3).
Checksum file (.sha256)Sent with the installer. Check it before you install (see 2.1). It confirms the file arrived complete and unchanged.

There are separate installers for each AI edition. Make sure you have the one that matches your licence:

InstallerEditionApprox. size
switchops-<version>-ubuntu24.04-local-3b.runLocal AI2.2 GB
switchops-<version>-ubuntu24.04-cloud.runCloud AI240 MB

Each installer is built for one Ubuntu release and one AI edition. It will not install on a different Ubuntu release, and it will not accept a licence for the other edition.

The installer checks this for you. A Local licence will not install from the Cloud installer, and the other way round.

1.2Server requirements

ItemLocal AI editionCloud AI edition
Operating systemUbuntu Server 24.04 LTS (any 24.04.x release), x86_64 (amd64)Same
CPU4 cores minimum, 8 recommended. Must support AVX2.2 cores minimum, 4 recommended
RAM8 GB minimum, 16 GB recommended4 GB minimum, 8 GB recommended
Disk40 GB minimum, 100 GB recommended (SSD)20 GB minimum, 40 GB recommended
GPUNot needed. AI runs on the CPU.Not needed
InternetNot neededOutbound HTTPS to your chosen AI provider
DevicesMinimum spec: up to about 50. Recommended spec: up to 100.Same

A virtual machine is fine (VMware, Proxmox, Hyper-V and similar). For the Local AI edition:

  • Set the VM's CPU type to pass the host CPU through (on Proxmox, CPU type host). Otherwise AVX2 can be hidden from the VM, and the AI becomes very slow.
  • Give the VM a fixed memory reservation, not ballooning or dynamic memory.

Not supported: Ubuntu Desktop, other Ubuntu releases (including 22.04), ARM servers, Debian, RHEL and its derivatives, Windows and macOS.

1.3Prepare the server first

Do these before you run the installer. The installer deliberately does not change the server's network settings, because doing that over an SSH session can cut you off halfway through.

  1. Install Ubuntu Server with a static IP address on your management network.
  2. Set the hostname, DNS and default gateway.
  3. Make sure you can reach the server over SSH with a user that has sudo.
  4. Make sure whiptail is present (it is on a standard Ubuntu install). If not: sudo apt install whiptail.

1.4Network access

1.5Device requirements

SwitchOps AI version 1.0 supports:

VendorPlatforms
CiscoIOS and IOS-XE routers and switches, including stacks
HuaweiS-series switches running VRP V200R0xx

SwitchOps detects the vendor automatically when it first logs in, so you add Cisco and Huawei devices the same way.

Each device needs:

  • A management IP address reachable from the SwitchOps server
  • SSH enabled
  • A login with full rights: on Cisco, a local user (or AAA account) with privilege level 15, or a user plus an enable secret; on Huawei, a local user with privilege level 15 and service type SSH
  • On Huawei, at least two free VTY lines. SwitchOps can use up to two SSH sessions to a device at the same time.

A minimal Huawei setup looks like this (replace the user name and password):

huawei
stelnet server enable
aaa
 local-user switchops password irreversible-cipher <password>
 local-user switchops privilege level 15
 local-user switchops service-type ssh
 quit
ssh user switchops authentication-type password
ssh user switchops service-type stelnet
user-interface vty 0 4
 authentication-mode aaa
 quit

You do not need to configure SNMP or syslog on the devices yourself. During discovery SwitchOps sets up SNMPv3 and points the device's syslog at the SwitchOps server for you, using the SNMPv3 credential you choose. This works the same on Cisco and Huawei.

02Installing SwitchOps AI

The installer is a guided, step-by-step wizard. A typical install takes 5 to 15 minutes, most of which is copying the AI model on the Local edition.

2.1Copy the installer to the server

From your workstation (example using scp):

bash
scp switchops-1.0.0-ubuntu24.04-local-3b.run switchops-1.0.0-ubuntu24.04-local-3b.run.sha256 youruser@10.0.0.50:/home/youruser/

Copy your licence file too if you already have it:

bash
scp switchops.lic youruser@10.0.0.50:/home/youruser/

On the server, check the file before you run it. Keep the .run and .sha256 files in the same folder:

bash
cd ~
sha256sum -c switchops-1.0.0-ubuntu24.04-local-3b.run.sha256

It should print OK. If it doesn't, copy the installer again.

2.2Run the installer

On the server:

bash
cd ~
chmod +x switchops-1.0.0-ubuntu24.04-local-3b.run
sudo ./switchops-1.0.0-ubuntu24.04-local-3b.run

The wizard opens in the terminal. Use Tab and the arrow keys to move, Enter to select.

2.3Step by step

  1. 1

    Prerequisites

    The installer checks the Ubuntu release, RAM and free disk.

    • Wrong Ubuntu release or a non-amd64 server: the installer stops and tells you which release it was built for. Use the installer that matches your server.
    • RAM or disk below the recommendation: it tells you what is short and asks whether to continue.
  2. 2

    Licence

    This comes first, so a licence problem shows up in seconds rather than after a full install.

    • The screen shows this server's machine fingerprint (a 64-character code).
    • No licence yet? Copy the fingerprint, press Cancel, and send the fingerprint to contact@switchops.tech or your SwitchOps representative. We send back your .lic file. Then run the installer again.
    • Have a licence? Enter the full path to it, for example /home/youruser/switchops.lic.

    When the licence is accepted you see a summary: licence ID, customer, plan, device limit, AI edition, add-ons and expiry date. Check it is what you bought.

    If the licence is rejected, the message says why (wrong machine, expired, damaged file). A "not bound to this machine" message also shows the fingerprint to send us.

  3. 3

    System name

    A friendly name for this SwitchOps system, for example HQ-NOC-01. It appears in the web interface and in reports.

  4. 4

    Database

    The installer sets up the database automatically. Nothing for you to enter.

  5. 5

    AI engine

    What you see depends on your licence:

    • Local AI: the installer explains that AI runs entirely on this server and installs the AI engine and model from the bundle. If the engine fails to start you get a clear warning; SwitchOps still installs and works, but AI analysis stays unavailable until it is fixed (see section 18).
    • Cloud AI: choose your provider and paste your API key.
      ProviderWhere to get a key
      Anthropic Claudeconsole.anthropic.com
      Google Geminiaistudio.google.com/app/apikey
      OpenAI (ChatGPT)platform.openai.com/api-keys
      DeepSeekplatform.deepseek.com
      The key is stored on your server only, readable only by the SwitchOps service. You can change the provider or rotate the key later from Settings → AI Agent.
  6. 6

    Install

    Program files, licence, configuration, services and the web server are installed. A progress bar shows each stage.

  7. 7

    Time synchronisation

    Enter an NTP server. On an isolated network use your internal NTP server. Accurate time matters: a wrong clock can cause licence checks to fail and makes incident timestamps misleading.

  8. 8

    Start

    SwitchOps starts, HTTPS is turned on with a self-signed certificate, and the final screen shows:

    • The address to open, for example https://10.0.0.50
    • Your plan, device limit, AI edition and expiry date
    • The commands to control the service

2.4Check the service

bash
sudo systemctl status switchops-backend

It should say active (running). Other useful commands:

bash
sudo systemctl restart switchops-backend      # restart SwitchOps
sudo journalctl -u switchops-backend -n 50     # recent service messages
sudo cat /var/log/switchops-install.log        # installer log

2.5Protect your encryption key

The installer creates a unique encryption key on your server. It protects every device password, SNMP key and API key stored in SwitchOps. It is held in /opt/switchops/.env.

Back up /opt/switchops/.env to a safe, offline place. If the server is rebuilt and this key is lost, all saved credentials have to be entered again.

Important

Do not run the installer again over a working system unless SwitchOps support asks you to. A fresh install creates a new encryption key, and credentials saved under the old key can no longer be read. For updates, contact support and we will send you the right update package.

06Inventory and discovery

Inventory is your single list of every network device.

6.1Device states

StateMeaning
ManagedFully discovered. SwitchOps can poll, monitor and configure it.
DiscoveredSeen and identified, but not fully managed yet (for example SNMP is not working).
UnreachableDid not answer ping.
No SSHAnswered ping, but SSH login failed.
DiscoveringDiscovery is running now.

A separate Reachability column shows live status: Up, Down, Recovery, Unstable or Unknown. SwitchOps pings every device once a minute in the background, so reachability stays current on the dashboard even when nobody has Live Ping open. A device is marked Down after two missed checks in a row, which opens a Device Unreachable incident; it closes on its own when the device answers again.

6.2Discover a device

  1. In Inventory, add a device: enter its IP address, choose the device type, role and location, and pick the SSH and SNMPv3 credentials.
  2. Start discovery. You can watch each step:
StepWhat happens
ICMP PingChecks the device is reachable
SSH ConnectLogs in with your SSH credential
Reverse PingThe device pings back to the SwitchOps server
Push SyslogPoints the device's logs at SwitchOps
Push SNMPv3Sets up SNMPv3 on the device
Verify SNMPv3Confirms SNMP works
Data PollCollects model, serial, versions, uptime, interfaces and more

On a Huawei switch the steps are the same. SwitchOps uses the matching Huawei commands for syslog and SNMPv3.

When every step passes the device becomes Managed.

You can also add devices you do not manage (for example a firewall or a provider's router) as non-managed devices, so your inventory is complete. They can be discovered later.

6.3Stacks

Each stack member is listed as its own device, because each has its own serial number. A four-switch stack appears as four devices and counts as four towards your licence.

6.4What you can see and do

  • Hostname, IP, vendor, model, device type, serial number, MAC, hardware and software version, uptime, role, location and notes
  • Search, filter and sort on any column
  • Add notes; each edit records who made it and when
  • SFP Modules tab Pro: every optical module across the network, with RX/TX power rated Good, Medium or Poor so you can spot failing optics early

Click any device to open its detail page.

07Device detail

The device page gives you everything about one router or switch.

TabWhat it shows
Device HealthCPU, memory, temperature, flash usage and uptime, with history
InterfacesPort table with status, mode, VLAN, speed, duplex, description and error counters. Includes PoE budget and interface configuration (see 7.1)
VLAN InfoThe device's VLANs and which ports use them

On Huawei switches, ports with no link type set (shown as auto on the switch) negotiate their mode. Unless a neighbour negotiates a trunk they carry untagged traffic in their default VLAN, so the Interfaces tab shows them as Access in that VLAN. Trunk ports show their allowed VLANs and native VLAN, on every vendor.

Use Poll Device to refresh the data immediately.

7.1Interface configuration

Change ports directly from the device page: description, shutdown, access VLAN, voice VLAN, mode, speed, duplex and more. You can select several ports and change them together.

Trunk VLANs are handled safely:

OptionWhat it does
Add VLANs (default on existing trunks)Adds VLANs to what is already allowed. Nothing else changes.
Remove VLANsRemoves only the VLANs you list. Asks you to confirm if VLAN 1 or the native VLAN is included.
Set listReplaces the whole allowed list. Default when you turn a port into a new trunk. On an existing trunk it shows you the current list and the new one before you confirm.

Enter VLANs as 60,70,80 or ranges like 100-110. Invalid entries are rejected before anything is sent. If you add a VLAN that does not exist on the switch yet, you get a warning.

On Huawei switches the same editor sends Huawei commands. Two things work differently from Cisco:

  • A new Huawei trunk carries only VLAN 1 until you list more. Always fill in the VLANs a new trunk needs.
  • Huawei adds VLANs to a trunk rather than replacing the list, so Set list first clears the allowed list and then sets the new one.

Custom interface templates work on both vendors. A few settings have no Huawei equivalent (Disable DTP, Storm Control Action, ARP Inspection Trust and Disable CDP); the preview marks them as left out and they are not sent.

10Incidents and AI analysis

SwitchOps turns device events (syslog, reachability, health and interface changes) into incidents you can track to closure.

10.1Priorities

PriorityTypical examples
P1 CriticalDevice unreachable, power or fan failure, stack link failed, WAN interface down, very high CPU or memory
P2 HighRouting neighbour lost (OSPF, EIGRP, BGP), Layer 2 loop symptoms, unexpected reboot
P3 MediumHigh errors, discards or utilisation on interfaces, PoE faults, high temperature
P4 LowInformational issues worth knowing about

Repeated signals for the same problem are grouped into one incident with an occurrence count, so you are not flooded.

10.2Incident list

  • Filter by priority, status, location and time range, with quick presets
  • Statuses: Active, Pending (awaiting acknowledgement) and Resolved
  • Export PDF produces an incident management report: summary, priority breakdown, incidents by location, most affected devices and the full log

10.3Inside an incident

Open an incident to see:

  • What happened, on which device, where, when it started and how many times it has been seen
  • The raw device message
  • AI analysis: likely root cause, how sure the AI is (with a confidence breakdown), and suggested steps and commands to check and fix it
  • History: a timeline of everything that happened (raised, came back, notes, acknowledged, resolved), newest first
  • Seen before: if the same issue happened earlier, a link to the earlier incident

You can add a note at any time ("Called ISP, ticket 4471"). Notes are kept in order and never overwritten.

10.4Resolving and reviewing

When you resolve an incident, a short review asks what happened:

  • AI fix worked
  • Fixed another way (tell us what you did)
  • Partly fixed
  • Not a real problem
  • Expected or planned work
  • Cleared by itself
  • Duplicate

You can also note the actual root cause, a tip for next time, the command that proved the cause, and whether the priority was right.

This is how SwitchOps learns your network. The next time a similar issue appears, on the same device, nearby, or anywhere in the network, the AI is given your engineers' verified fixes first. Its advice gets more specific to your environment over time.

If an incident clears on its own, you can still open it and Review it later.

Settings → AI Agent → AI accuracy shows how often the AI's advice was right according to your engineers' reviews.

11Configuration push

The Configuration page has three tabs: Device Configuration, Interface Configuration and Push History.

Configuration push is available to Network Engineers and Super Admins, for routers and switches.

If you manage more than one vendor, a vendor switch at the top of the Configuration page picks Cisco or Huawei. Everything below follows it: the device list, the templates, the CLI preview, push and rollback. One push never mixes vendors, so the preview is exactly what each device receives. SwitchOps remembers the last vendor you picked.

11.1Ready-made templates

Fill in a form, preview the exact CLI, then push. Included templates:

AreaTemplates
BasicsBanner MOTD, Local Users, NTP Configuration, NTP Authentication, Logging & Syslog, DHCP Pool Configuration
Security hardeningSSH Security, Line Hardening (VTY/Console), VTY Access Control, AAA Configuration, Global Services Hardening, Interface Hardening, Disable CDP, SNMP Access-List, Access Control List, Config Archive Logging

For Huawei, the templates send Huawei commands. Some Cisco templates have no Huawei version and are hidden when Huawei is selected: Policy Map / QoS, EIGRP Routing, Fault & Memory Reserves, Config Archive Logging and Disable CDP. UDLD Configuration sets up DLDP, the Huawei equivalent.

Huawei also has its own templates:

Templates that change management access (SSH Security, Line Hardening, VTY Access Control, SNMP Access-List and AAA) can lock you out if a value is wrong. Try them on a test switch first, or keep console access ready.

Interface configuration cards cover common port settings. Pro plans can also create custom interface templates.

11.2How a push works

  1. Pick the target devices. Only routers and switches appear.
    • Basic plans: one device per push.
    • Pro plans: several devices, or Select by location to pick every device at a site (including its buildings and floors). Offline devices are listed but left unticked.
  2. Choose one or more templates and fill them in.
  3. Review the Summary and CLI Preview. Before anything is sent, SwitchOps checks the push and warns you about lines that cannot be rolled back (for example crypto keys or certificates).
  4. Choose how to push Pro:
    • Sequential: one device at a time, safer. Can stop at the first failure.
    • Bulk: all devices at once, quicker.
  5. Choose whether to Save to startup-config. Unticked (default) changes the running configuration only, so a reload brings back the saved config. Ticked saves at the end, after all templates. On Huawei this runs the save command.
  6. Start the push and follow the Push Log live.

For a location push of more than 10 devices, you are asked to type the location name to confirm.

11.3Checkpoints and rollback Pro

  • Before the first template, and before each next template, SwitchOps takes a checkpoint of the device configuration
  • Each device keeps its last 10 checkpoints
  • From Push History you can roll a device back to any checkpoint. SwitchOps works out the difference and pushes only what is needed, and tells you what will happen before you confirm
  • Rollback is available to Network Engineers and Super Admins
  • Rollback works the same on Huawei. SwitchOps works out the Huawei undo commands, including multi-line banners

11.4Push History

Every push is recorded: who pushed, when, what was pushed, to which devices (or which location), the vendor, and the result per device. Passwords and keys in templates (local users, SNMPv3, NTP keys, AAA shared keys) are hidden in the CLI preview and stored as <hidden> in Push History; the device still receives the real value.

12.2AI Agent

13Email alerts Pro

Pro

Pro feature (Pro, Pro+ and Trial). Works in both Local and Cloud editions and does not use AI.

Go to Settings → Email Alerts.

13.1Mail server

Enter your SMTP relay (host, port 25 / 587 / 465, security None / STARTTLS / SSL/TLS, optional username and password) and the From address. Use Send test email to check it. Errors are shown in plain words, for example "authentication failed" or "relay denied".

13.2Mail templates

Each template decides who gets what:

  • Recipients: one or more email addresses
  • Subject: with placeholders such as {priority}, {title}, {hostname}, {location}
  • Filters: priority (P1 to P4), location, device, device type, and System
  • Events: Raised, Resolved, Recurring

How filters combine: inside one template all filters must match; values inside one filter are "any of". An empty filter means "any". Choosing a location includes everything under it.

If someone is listed in two matching templates, they get one email, not two.

13.3Keeping alerts useful

  • Hold-down: an alert waits a short time (2 minutes by default, adjustable) before sending. If the problem clears inside that window, no email is sent. A flapping port does not fill your inbox.
  • Storm guard: if a big failure triggers many alerts at once, recipients get one summary email instead of dozens.
  • Retries: if the mail server is down, emails are queued and retried, and are not lost on a restart.

13.4System alerts

Tick System on a template to be told about SwitchOps itself:

  • Licence expiring (30, 14, 7, 3 and 1 day before), grace period started, licence expired
  • Device count reaching 80% and 100% of your licence
  • SwitchOps server CPU, memory or disk staying high
  • AI engine down, and back up again
  • A scheduled backup failed

13.5Delivery log

Shows the last 500 sends with the result: sent, failed (with reason) or held back (with reason). This is the first place to look if someone did not get an alert.

Restoring a system backup asks you to confirm, because it replaces current data.

Good practice: download a system backup regularly and keep it off the server, together with your copy of /opt/switchops/.env (section 2.5).

15Licensing

15.1How licensing works

  • Licences are offline files. No connection to SwitchOps is ever needed to activate or check them.
  • A licence is tied to your server's fingerprint. If you reinstall the operating system, replace the network card or move to new hardware, the fingerprint changes and you need a reissued licence. Contact us with the new fingerprint.
  • One device = one serial number. A four-member stack counts as four devices.

15.2See your licence

Settings → System Info shows plan, AI edition, issue and expiry dates, days left, devices used against your limit, and add-ons.

15.3Install a new licence

For renewals and upgrades we send you a new .lic file. A Super Admin installs it from Settings → System Info → Install new licence. The new file is checked before it replaces the current one, so a wrong file cannot break a working system. New features unlock straight away, without a restart.

To read the server's fingerprint at any time:

bash
sudo /opt/switchops/bin/license_tool fingerprint

15.4When a licence nears its end

StageWhenWhat happens
NormalUntil 14 days before expiryEverything works
WarningLast 14 daysEverything works; a banner reminds you
GraceUp to 7 days after expiryEverything works; a stronger banner
Read-onlyAfter the grace periodYou can still view monitoring, inventory and reports, but changes are blocked until a new licence is installed

The same read-only mode applies if the licence is missing, damaged, or the server clock has been set back. Keep NTP working.

15.5Device limit

When your inventory reaches the licensed number of devices, new discoveries are blocked. System Info shows how close you are, and System alerts (section 13.4) can warn you at 80% and 100%.

15.6Moving between Local and Cloud AI

Local AI and Cloud AI are separate editions. Moving from one to the other is a new purchase with a new licence and the matching installer. Your system backup can be restored into the new installation. Contact us to plan the move.

16Cloud AI and your data

Note

This section applies to the Cloud AI edition. The Local AI edition sends nothing off your server.

Every request to the cloud AI provider goes through a privacy filter on your server first.

Never sent: passwords and secrets, enable secrets, SNMP community strings and SNMPv3 keys, TACACS/RADIUS and routing keys, pre-shared keys, certificates, serial numbers (including Huawei ESNs) and email addresses. Huawei encrypted password values are removed too.

Masked before sending, restored in the answer: IPv4 and IPv6 addresses, MAC addresses and domain names. The AI can still reason about subnets and gateways, and your engineers see the real addresses in SwitchOps.

Sent as is: hostnames, interface names, VLAN IDs, device models, software versions, counters and log text. These carry the diagnostic value.

If masking fails for any reason, nothing is sent.

See it for yourself: Settings → AI Agent → Privacy protection → Show what is sent displays the exact masked request for an incident, without sending anything. Share this with your security reviewer.

Your API key is stored encrypted on your server and is shown only as its last four characters.

18Troubleshooting

Installer says the licence is not for this machineThe server's fingerprint changed (OS reinstall, new network card, new hardware). Send the fingerprint shown on screen to support for a reissued licence.
Installer says the licence is for the other editionYou have the Local installer with a Cloud licence or the other way round. Ask us for the matching installer.
Installer says it is for a different Ubuntu releaseThe installer is built for one Ubuntu release (it is in the file name). Install on Ubuntu Server 24.04 LTS, or ask us for the matching installer.
